# Deep review, October 2026

Subscription `/login` was broken on every v0.1.x binary, and so were image reads. Every test
passed anyway, because every test ran from source. This review did two things about that.
It added the test layers that run the **compiled binary** (see [TESTING.md](TESTING.md)).
Then it read the whole system, one subsystem per reviewer, and fixed what they found.

Each fix below has a regression test, and each test was run once against the unfixed code to
watch it fail. Where a test could not be made to fail, or a finding was left, the entry says
why.

## How the binary-only bugs got through

| Bug | Why only the binary had it | What now catches it |
|---|---|---|
| `/login` → subscription: `Cannot find module './anthropic.js'` | pi-ai loads its OAuth flows with a computed `import()`, so `bun build --compile` never bundles them | `src/runtime/bun-setup.ts` registers them. The terminal e2e test opens every subscription flow. The bundle guard fails on any new computed `import()` in a dependency. |
| Bedrock models fail to load | Same, for the Bedrock provider | Registered in `bun-setup.ts`; the bundle guard requires the registration |
| Image reads return "Image omitted" | The photon decoder reads its `.wasm` from the build machine's `__dirname`, which was baked into the binary | The wasm is embedded and served from the binary. The binary e2e test reads a PNG. The bundle guard fails on any unhandled baked `__dirname`. |

Left:
- `distrusted` is still a difference, not a ratio.
- Skill nodes are still global by label.
- A write that times out on the client can still be applied later.
- Embedding still runs under the journal lock, because moving it out is not a contained change.

`tests/ann_probe.rs` is marked `#[ignore]` with a reason: it is a temporary probe that took about 190s.
