Speaker gutters — the current set, from the code

These are the real values shipping today (generated above). Each is a two-cell figure — the pixels of a 2×2 sprite — and each is meant to tell you who is speaking before you read a word, which one character cannot do:

Heavy — the shipping set: █▄ you U+2588 U+2584 █▌ agent U+2588 U+258C ░▄ thinking U+2591 U+2584 ▐▌ tool U+2590 U+258C ramp: ░ ▒ ▓ █ (5 levels, lightest to densest)

Two columns, and the air beside the prose is the figure's own half-empty right pixel rather than a space after it — so the gutter costs the transcript exactly what the one-character version did, and no line re-wraps. The candidates below are kept as the reasoning behind these four; what shipped, every pose and the art as you edit it, is docs/design-preview.html.

The target: block figures instead of letters

Two columns, one row tall, built from blocks so the shape carries the meaning and colour only reinforces it. Three candidates — this is the part worth arguing about:

Solid marks, meander-adjacent. Reads as pottery stamps.

Block headers with a portrait

The richer idea, and the one that earns the word sprite: the first line of a block carries a 2×2-cell portrait, and continuation lines carry the pipe. Two rows per block rather than per line, so it costs almost nothing and gives the transcript a face:

Mascots — three simple creatures

The cat is being retired: it was detailed enough that nobody redrew it. These are 5×3 cells, drawn from half-blocks, each with an idle pose, a blink, a bob and a thinking pose. Hand-redrawable in thirty seconds is the test.

Crab — the reference register

Wide, low, obvious. The one to reach for when the splash needs to feel friendly.

Amphora — from the palette direction

Upright and classical; reads as a vessel rather than an animal, which suits a memory system.

Owl — the one that watches

Two eyes already means “attention”; the thinking pose reuses them as the pulse.

Frame changes do not resize: every frame of a sprite keeps its siblings’ dimensions, or the animation jitters the layout around it. That is a tested invariant, not a habit.

Motion — springs, and when they stop

Motion comes from charm.land/harmonica with one preset per purpose rather than per component. Below is the same physics the Go package will use, simulated live so the differences are visible:

snappy — a block appearing, a fold opening

soft — an overlay arriving or leaving

slow — the live indicator’s pulse

frames drawn: 0 — a spring that has settled asks for no more frames.

The rule that matters: the app asks one question — does any spring still need a frame? — and the redraw loop stops when the answer is no. An interface that repaints forever wakes the terminal, drains a battery, and makes “is it stuck?” unanswerable.

And it is optional: MNEMO_NO_ANIMATION=1 jumps every value straight to its target, and one tick reports itself settled. Terminals get recorded and read back.

The thinking state

Where the interface spends most of its time, and the least designed thing in it. Three changes: a live line while it works, folding that carries the real duration, and history that recedes along the dither ramp instead of switching to a second colour.

Logs — two kinds of thing, labelled

The pane holds trace spans (a tree) and log lines (structured, level + key=value) and says which is which, because conflating them is how a diagnostic surface stops being useful:

─ spans ──────────────────────────────────────── ● turn 2026-09-17T10:41Z bash_exec 312ms ├─ spawn 48ms └─ exit 0 ─ log ────────────────────────────────────────── DBUG session attached provider=opencode-go model=deepseek-v4.1 INFO permission granted pattern=npm test* scope=project WARN frame dropped reason=spring-window-exceeded

Written to ~/.mnemo/logs/mnemo.log — never to stdout, because a stray log line corrupts the frame the interface owns.
