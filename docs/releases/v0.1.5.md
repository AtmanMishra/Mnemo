## What's new

### Agents that work in teams
- **Sub-agents can start sub-agents.** Down to three levels, four live children per
  agent and sixteen per conversation. A read-only agent can only start read-only
  ones, and `spawn_subagent` takes a `name`.
- **Sibling agents.** In the agents page, `l` on one agent and `l` on another links
  them. Each can then see what the other is doing (`list_agents`) and message it
  (`message_agent`), and a sub-agent can reach its parent's siblings. `u` unlinks.
  Only you can link agents; there is no tool for it.
- **The agents page draws the tree.** A card says who the agent is linked with and
  how many sub-agents it has; under the cards, the selected agent's family as a tree
  with each sub-agent's task and steps.
- **The playground (`ctrl+y`, or `p` in the agents page)** shows every agent,
  sub-agent and message between them, live. It is for supervising: no prompt, no
  stop, no messages. `enter` takes you to the agent, where you can talk to it.

### Split view
- Never more than four panes. `alt+l` cycles the layouts that make sense for the
  count: columns, rows, grid, main + side.
- `f` in the agents page splits an agent with its family: linked agents first, then
  its busiest sub-agents. The bar says `4 of 9` when more are related. A sub-agent
  is a read-only pane (task, steps, answer).

### Safety
Messaging between agents is a new way for text to reach a model, so it was designed
and reviewed as one (`SECURITY.md`, "Agents that talk to agents"):
- Who may message whom is a rule in code (`Roster.canReach`), the same refusal for
  "no such agent" and "not yours".
- A message is framed as another model's text, never put in the system prompt, grants
  nothing, and never starts a turn. The receiver's approvals work as before.
- Size, rate, inbox, depth and fan-out are bounded; a sub-agent never has more access
  than its parent.
- Everything an agent writes is stripped of control and bidirectional characters and
  redacted before it is shown or delivered.
- The playground has no way to change anything, and a test types at it to prove it.

### Known
- You talk to top-level agents only; sub-agents are watched, not typed to.
- A message never wakes an idle agent: a sibling reads it at its next prompt.
- Links last for the session; they are not restored on restart.
